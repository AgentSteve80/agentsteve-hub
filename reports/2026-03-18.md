### 1. 🚨 CVE-2026-3888 — Ubuntu 24.04 Root Escalation via snap-confine + systemd-tmpfiles (CVSS 7.8)
**Source:** The Hacker News · Qualys TRU · March 18, 2026
**Relevance: 10/10** | `#ubuntu` `#linux` `#privilege-escalation` `#critical` `#direct-hit`

**This hits our exact OS.** Qualys TRU disclosed CVE-2026-3888: an unprivileged local attacker on Ubuntu 24.04 (default install) can escalate to full root via a timing interaction between `snap-confine` and `systemd-tmpfiles`. The exploit requires the system to have been running for 10–30 days without a tmpfiles cleanup cycle — which means **our VM almost certainly qualifies**. The interaction: snap-confine creates a sandbox dir in `/tmp`, systemd-tmpfiles eventually cleans it, and the window between creates a race condition exploitable for privilege escalation.

**So what:** We're on Ubuntu 24.04.4. This is a local privilege escalation — an attacker who already has a low-priv shell on our box can become root. Combined with the CrackArmor AppArmor flaws flagged this week, our attack surface at the kernel/OS layer is wide open right now. **I can patch immediately**: `sudo apt-get update && sudo apt-get upgrade snapd systemd`. Want me to run it?

🔗 https://thehackernews.com/2026/03/ubuntu-cve-2026-3888-bug-lets-attackers.html

### 2. 🚨 9 Critical IP KVM Flaws — Unauthenticated Root Access Across 4 Vendors
**Source:** The Hacker News · Eclypsium · March 18, 2026
**Relevance: 9/10** | `#hardware` `#kvm` `#infrastructure` `#rce` `#critical`

Eclypsium disclosed 9 critical vulnerabilities across four IP KVM products (GL-iNet Comet RM-1, Angeet/Yeeso ES3, Sipeed NanoKVM, JetKVM). Common themes: missing firmware signature validation, no brute-force protection, broken access controls, exposed debug interfaces. The worst flaws allow unauthenticated root access or arbitrary code execution — at the BIOS/UEFI level, bypassing all OS-level security controls.

**So what:** If any of these KVM products are used for remote access to the Mac Mini M4 or any server in the low-voltage company, this is a critical patch-or-pull. Even if not currently in the stack: when evaluating remote access hardware for field deployments (job site cameras, remote access to install systems), avoid the four named vendors until firmware is patched. The BIOS-level access angle makes this especially nasty — no OS security control helps once an attacker has KVM access.

### 3. 🚨 Apple CVE-2026-20643 — WebKit Same-Origin Policy Bypass on iOS/macOS
**Source:** The Hacker News · March 18, 2026
**Relevance: 9/10** | `#apple` `#ios` `#macos` `#webkit` `#zero-day`

Apple released an emergency "Background Security Improvement" update to patch CVE-2026-20643 — a WebKit cross-origin issue in the Navigation API that allows bypassing the same-origin policy via malicious web content. Affects iOS 26.3.1, iPadOS 26.3.1, macOS 26.3.1 and 26.3.2. Fixed in iOS 26.3.1(a) and macOS 26.3.1(a)/26.3.2(a).

**So what:** Update the iPhone (Pal app test device) and Mac Mini immediately. Same-origin bypass means a malicious website can read cross-origin data — session tokens, cookies, other open tabs' content. The Pal app uses WebView for auth flows (Clerk), so an attacker targeting field techs via a malicious link could potentially hijack sessions. Fast patch; Apple's Background Security Improvement mechanism means it can install without a full OS update.

🔗 https://thehackernews.com/2026/03/apple-fixes-webkit-vulnerability.html

### 7. AI DNS Exfiltration in Amazon Bedrock, LangSmith & SGLang Sandboxes (BeyondTrust)
**Source:** The Hacker News · BeyondTrust research · Morning brief
**Relevance: 9/10** | `#ai` `#security` `#aws` `#langchain` `#sandboxing`

BeyondTrust disclosed a covert exfiltration method in AI code execution sandboxes: outbound DNS queries used as data exfiltration channels or interactive shell tunnels. Affects Amazon Bedrock AgentCore, LangSmith, and SGLang sandbox environments — all three didn't block DNS egress from agent sandboxes.

**So what:** If Mission Control ever runs AI-generated code in sandboxed environments, DNS egress must be blocked at the network layer (not just firewall rules — DNS is UDP/53 and often allowed through). This also applies to our OpenClaw exec tool: any untrusted code execution path should have DNS egress blocked. For SiteSignal's scrapers running in Docker: verify the Pi-hole container doesn't have outbound DNS enabled for user-submitted code.
